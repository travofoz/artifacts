Eph / Spec v0

: eph it :

Spec-driven scaffold for building throwaway-to-persistent apps fast, with AI ride-along as a first-class citizen. Built for constrained connectivity and solo iteration — runs great from a phone, works just as well on desktop. Not a framework — a set of Legos assembled per app, scoped to expected lifespan.

§1

Tiers — lifespan drives stack, not preference

TIER 0hours→1 day

Single HTML file. Vanilla JS + fetch. No build step. Turso/libSQL WASM in-browser if state needs client-side persistence. Deploy: none, or GitHub Pages static.

TIER 1days→1 week

SvelteKit alone — no Express, +server.js routes are the API layer. Vite 8 for WS streaming. Deploy: static build + one Cloudflare Worker for the dynamic endpoint; VPS only if persistent background state is required.

TIER 2persists / matters

Next + SQLite (libSQL) — no ORM by default. Raw SQL, Kysely, or DSANDSL-stripped if leaning on it across apps. Hand-built and reviewed, not spec-looped. Technical debt tradeoffs apply here; they don't at Tier 0/1.

§2

The Legos — bill of materials

L-01

AI ride-along / tool registry

Included
  • Build-time: AST walker (acorn) over route files → parses JSDoc tool-block → emits JSON tool manifest. Reuses TADA's pattern.
  • Runtime: ARIA + custom data-attrs as UI-awareness layer — "AI is a screen reader."
  • Meta-tools: navigate, event, api, annotate, lightbox, save-macro, stop (caps registry bloat).
  • Portable across Tier 0/1 — vanilla JS + DOM APIs, no framework dependency.
L-02

DB adapter

Included
  • libSQL client, local file by default. syncUrl → Turso Cloud opt-in only.
  • Native vector search + FTS (Tantivy) built into Turso Database — covers semantic + full-text without extra pieces.
  • Graph modeling: adjacency table + recursive CTEs. Real graph work deferred to CogOS/HelixDB.
  • Sync conflict resolution: last-write-wins at row level. Flag if an app ever goes multi-writer.
L-03

Webhooks — in / out, rich

Included
  • In: triggers self-heal pipeline (L-06), external event ingestion.
  • Out: notify/alert dispatch — push, webhook-out, in-app flag for next open.
  • Ingestion/polling (ADS-B, prices, solar, etc.) lives here: poll → normalize → diff-against-last-state → store → maybe-alert.
  • Change-detection named explicitly — core of every situation-monitor use case.
L-04

Secrets / config management

Included
  • Local secrets store, explicitly outside the AI tool registry's read/write boundary.
  • No env-baked-at-build for anything rebuilt often — defeats the point of ephemeral.
L-05

Rate-limit / cache layer

Included

TTL cache wrapping the fetch tool. Default-on for any external API call the tool registry makes — prevents an afternoon app from getting banned or billed.

L-06

Self-healing pipeline

Included

AI can't answer → opens GitHub issue → triage agent evaluates → spins feature branch → generates PR → human review. Packaged as its own reusable Lego, not reimplemented per app.

L-07

Offline / connectivity handling

Included

Queue-and-retry for writes, stale-while-revalidate for reads. Built for spotty connectivity as the default, not the edge case.

L-08

UI kit + theme builder

Included
  • Fork shadcn (not DaisyUI) — copy-into-repo by design, no dependency to vendor/fight.
  • Trim to 8–10 owned primitives: Card, Modal, DataTable, Calendar, Chart (Apache ECharts + echarts-gl — wide series coverage plus WebGL 3D/globe out of the box; not scoped to one problem, heavier is fine here since ephemeral apps get refactored down later if they ever need to), CardFeed, +2–3 TBD.
  • Theme builder = tokens only (color, spacing, radius, shadow, font). Primitives read tokens, never hardcode classes — reskin = edit one file + regenerate.
L-09

Observability

Included

errplay generalized from client-error-capture into a small always-on ingest endpoint + dashboard, reusable per app. Already dogfooded — most proven piece in the kit.

L-10

Graph modeling

Deferred

Not rejected — deferred. Adjacency table + recursive CTEs cover current needs. Real graph modeling stays scoped to CogOS/HelixDB until this kit has a genuine multi-hop use case.

L-11

Canvas / simulation (three.js)

Included
  • Never a Tier 1 default — opt-in per app, not bundled.
  • Covers 3D charts, spatial/graph visualization, and general animation or simulation canvas work.
  • Chart primitive (L-08) already covers 3D/WebGL via echarts-gl — L-11 is for non-chart spatial work: custom scenes, simulation, spatial UI, animation.
L-12

Audio

Included
  • Analysis: native Web Audio AnalyserNode — FFT/waveform data, no library needed.
  • Tone generation, synthesis, effects: Tone.js.
  • Speech-to-text: out of scope for now — device keyboard/dictation already covers it on Android; revisit only if a real gap shows up.
L-13

Media capture — webcam / mic / system audio

Included
  • getUserMedia for webcam + microphone, getDisplayMedia for system audio.
  • Standard browser APIs — identical on desktop and mobile, no platform-specific code.
  • Capture stays separate from L-12: this produces the stream, L-12 consumes/analyzes it.
L-14

State (nanostores)

Included
  • Opinionated on purpose — one state primitive across all tiers, so an app author (or the orchestrator) never re-solves this per app. Atom / map / computed is the whole vocabulary: no reducers, no actions boilerplate, no provider wrapping.
  • Implements Svelte's store contract natively — same primitive works unmodified in Tier 0 vanilla and Tier 1 SvelteKit, no adapter layer.
  • Built-in persistent store covers L-04-adjacent config/local persistence; built-in async computed store covers L-03's ingestion/polling state chains — not hand-rolled per app.
  • Excludes: global Redux/Zustand-style shared-schema state stores — see §4.
L-15

Event bus / IPC

Included
  • Separate from L-14 on purpose: state answers "what is true right now" (queryable, has a value at rest); events answer "something happened" (transient, meaningless to query after the fact unless something explicitly recorded it).
  • Native EventTarget or a small custom emitter — zero dependency, same portability guarantee as L-01/L-14: identical primitive in Tier 0 vanilla and Tier 1 SvelteKit.
  • This is the actual answer to "how do Legos talk to each other" — L-03's webhook fire, L-07's connectivity-restored, L-06's critic-passed all emit here rather than being wired Lego-to-Lego directly, which would recouple everything.
  • Anti-pattern to avoid: don't poll a state atom to detect an action, and don't store a transient event as a never-cleared state flag — that's each primitive doing the other's job.
§3

Deploy defaults

Default

GitHub Pages (free) + GitHub Actions build + Cloudflare for domain.

Escalate

Cloudflare Worker — only when a dynamic endpoint is unavoidable.

Escalate

VPS — only when persistent always-on state (L-03 ingestion scheduler, etc.) is required. Not a default.

§4

Explicitly excluded

Decisions made in the negative — not gaps, deliberate exclusions. Don't reintroduce without re-litigating.

PRISMA / ORMs by default

Dropped for silently unsupported Postgres interval/datatype behavior in a revenue-attribution context — unacceptable where precision matters. No ORM is the default across all tiers; Kysely / DSANDSL-stripped are opt-in exceptions only.

EXPRESS as default pairing w/ SvelteKit

Redundant — +server.js is the API layer. Only reintroduce for genuine deploy-lifecycle decoupling or a WS case SvelteKit/Vite can't cleanly own.

DAISYUI

Vendored Tailwind plugin fights the fork-and-own workflow. shadcn is the fork target instead.

MYSQL

Contradicts the single-writer, low-dependency default. SQLite/libSQL is default; multi-writer server DB is a Tier-2-only escalation if ever actually needed.

TYPESCRIPT

JS + JSDoc for IDE hinting, no compile-time checking, no exceptions.

GRAPH DB as a kit Lego

See L-10 — deferred, not rejected.

GLOBAL STATE STORES (Redux/Zustand-style shared schema)

Would force every Lego to agree on one shared shape — contradicts the point of L-14. Nanostores' atomic model (independent atoms per concern) is the default instead.

§5

Testing & linting — two different disciplines

LINTINGstructural / AST

Zero-tolerance, rigid by design — checking form, not judging outcomes. Enforces L-01's contract directly: nothing passes the pipeline without a JSDoc tool block on every route, or without required ARIA + data-attrs on every interactive element. Rigidity is safe here specifically because there's no solution-space diversity worth preserving on a yes/no structural question.

TESTINGbehavioral / outcome

Two-layer, both outcome-based, neither prescribes mechanism:

  • Lego contract tests — ship with each Lego, black-box its boundary (given real inputs, does it produce the promised behavior). Reused unchanged by every app that pulls the Lego in.
  • App-level e2e — written per app, tests the assembled flow only. No unit tests except proven-sticky regressions once a failure point is shown to recur — that's the deliberate exception, not the default.
